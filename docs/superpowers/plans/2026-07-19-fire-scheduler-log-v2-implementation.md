# Fire scheduler and Log V2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 将抢购执行改为可控、可复现的单一 run 调度链：自动/手动/burst 模式都通过统一的绝对时间 slot 与状态机执行，保留一条可恢复的日志真值链路（Log V2）。

**Architecture:** 继续保留 `content script` 为编排边界，新增 `lib/api` 中的纯函数调度与运行器，保留 `src/bm-main` 中的 MAIN-world 网络桥接与视觉记录层。所有跨世界通信使用显式事件携带 `runId/shotId/requestId`，并保持现有按钮与 V1 UI 的兼容入口不变。

**Tech Stack:** TypeScript, Vitest, WXT 测试工具, IndexedDB (原生), Chrome extension APIs, vanilla JS（MAIN world script bundle）。

---

## Final implementation decisions

- `executeShot` receives `requestId`, `onFetchStarted`, and `setAbort`. Cancellation returns only unstarted `reserved` or `released` tickets, transitions them to `returned`, and never returns `fetch-started` tickets or writes them back as `available`.
- `DO_FETCH_STARTED` carries `MainWorldFetchStartedTiming`; only `DO_FETCH_RESULT` carries the complete `MainWorldTransportTiming`. Isolated-world callbacks are removed before `postMessage`, and timeout or abort sends `DO_FETCH_CANCEL`.
- Auto scheduling uses the full measured RTT: `fireStartMs = targetMs - rttCompensationMs - 10 - clockOffsetMs`, `prepareAtMs = fireStartMs - 3000`, `startMs = fireStartMs`, and `earlyOffsetMs = 10`.
- The content entry point captures `Date.now()` and `performance.now()` together. Duration fields prefer the monotonic delta, while epoch timestamps remain available for correlation.
- `public/bm-main.js` is generated by `pnpm build`; do not stage or commit it.

```ts
export type FireMode = 'manual' | 'burst' | 'auto';

export interface FireShotSlot {
  shotId: string;
  productId: string;
  productPriority: number;
  requestSeq: number;
  plannedAt: number;
}

export interface FireScheduleInput {
  runId: string;
  mode: FireMode;
  startMs: number;
  intervalMs: number;
  shots: Array<{ shotId: string; productId: string; productPriority: number }>;
}

export interface FireSchedulePlan {
  runId: string;
  mode: FireMode;
  startMs: number;
  intervalMs: number;
  slots: FireShotSlot[];
}

export function buildFireSchedule(input: FireScheduleInput): FireSchedulePlan {
  const startMs = Math.max(0, Math.round(input.startMs));
  const intervalMs = Math.max(1, Math.round(input.intervalMs));
  return {
    runId: input.runId,
    mode: input.mode,
    startMs,
    intervalMs,
    slots: input.shots.map((shot, i) => ({
      shotId: shot.shotId,
      productId: shot.productId,
      productPriority: shot.productPriority,
      requestSeq: i,
      plannedAt: startMs + i * intervalMs,
    })),
  };
}
```

- [ ] **Step 2: `mainWorldFetch` 使用 requestId/runId/shotId 并转发 `onFetchStarted`**
```ts
function mainWorldFetch(opts: XhrRequestOptions): Promise<{ status: number; statusText: string; body: string; timing: MainWorldTransportTiming; headers: Record<string, string> }> {
  return new Promise((resolve, reject) => {
    const reqId = opts.requestId || Math.random().toString(36).slice(2);
    let settled = false;
    let timeoutId: ReturnType<typeof setTimeout> | undefined;
    const finish = (fn: () => void) => {
      if (settled) return;
      settled = true;
      window.removeEventListener('message', handler);
      if (timeoutId !== undefined) window.clearTimeout(timeoutId);
      fn();
    };
    const abort = (reason: 'aborted' | 'timeout' = 'aborted') => {
      if (settled) return;
      window.postMessage({ [MSG_CMD]: true, type: 'DO_FETCH_CANCEL', requestId: reqId }, '*');
      const error = new Error(reason === 'timeout' ? 'MAIN world fetch timeout' : 'MAIN world fetch aborted');
      error.name = reason === 'timeout' ? 'TimeoutError' : 'AbortError';
      finish(() => reject(error));
    };
    opts.onAbortReady?.(abort);
    function handler(ev: MessageEvent) {
      if (ev.source !== window || !ev.data?.[MSG_EVT]) return;
      if (ev.data.type === 'DO_FETCH_STARTED' && ev.data.requestId === reqId) {
        opts.onFetchStarted?.({ timing: ev.data.timing, requestId: reqId });
        return;
      }
      if (ev.data.type !== 'DO_FETCH_RESULT' || ev.data.requestId !== reqId) return;
      if (!ev.data.ok) {
        finish(() => reject(new Error(ev.data.error || 'fetch error')));
        return;
      }
      finish(() => resolve({
        status: ev.data.status,
        statusText: ev.data.statusText,
        body: ev.data.body,
        timing: ev.data.timing,
        headers: ev.data.headers,
      }));
    }
    window.addEventListener('message', handler);
    const messageOpts = toMainWorldFetchOptions({ ...opts, requestId: reqId });
    window.postMessage({ [MSG_CMD]: true, type: 'DO_FETCH', requestId: reqId, runId: opts.runId, shotId: opts.shotId, opts: messageOpts }, '*');
    timeoutId = window.setTimeout(() => {
      abort('timeout');
    }, 8000);
  });
}
```

`toMainWorldFetchOptions` removes both callback functions before posting the request because structured clone cannot carry functions. `DO_FETCH_STARTED` includes only the bridge-received and fetch-called fields already observed at that stage. Explicit abort and timeout use the same `abort` callback, emit `DO_FETCH_CANCEL`, and settle the isolated-world promise once.
